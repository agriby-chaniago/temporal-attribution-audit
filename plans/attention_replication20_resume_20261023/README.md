# Continue the 20-seed audit after the strict attention-mask error

The notebooks are generated by `scripts/build_nb_22_24_resume.py`. Do not edit
`.ipynb` sources manually. No old notebook, checkpoint or result needs deletion.

## What to run

1. Stop any original/FAST/resume handwriting notebook and wait until it is idle.
2. Open `notebooks/22_replication20_newhandpd_resume.ipynb`.
3. Select **Skripsi (.venv)**, then **Restart Kernel and Run All**. Keep the same
   environment, packages, GPU and runtime flags.
4. The checkpoint stage authenticates and reuses the 200 available models and OOF
   maps. The early alignment probe tests the failed seed-7/fold-4 recording before
   the long intervention loop. A passing probe permits continuation; a failed probe
   stops early with `runtime_alignment_trials.jsonl` and preserves all old caches.
5. Complete record caches from the original and FAST runs are reused. A partial
   recording replays its cached intervention points before continuing. Unsaved
   work can repeat. The repair does not lower any scientific completion criterion.
6. After NewHandPD completes, run `23_replication20_uci_sst_resume.ipynb`, then
   `24_replication20_joint_report_resume.ipynb` after both cohorts are complete.

If interrupted later, use Restart Kernel and Run All on the **same resume notebook**.
Do not run old and new versions concurrently. Locks from dead same-host processes
are handled by the existing mechanism; do not manually delete a live process lock.

No rebuild is required to use the supplied notebooks. For identical regeneration:

```bash
rtk proxy .venv/bin/python scripts/build_nb_22_24_resume.py
```

The builder refuses to replace changed executed notebooks or an already sealed
different execution. It runs no model or statistical analysis.

## Where results go

`results/attention_replication20_resume/<cohort>/<design_id>/<runtime_id>/<execution_id>/`

The existing model store is shared by authenticated checkpoint identity. Old
reference/FAST predictions and record caches are read-only inputs. Outputs include
the same scientific CSVs and figures as the parent design, plus:

* `runtime_alignment_trials.jsonl`: numerical differences, exact mask mismatches,
  candidate profile ID, attempt/repeat and failure/resource diagnostics.
* `runtime_alignment_profiles/<model_id>/<idx>.json`: immutable first passing
  registered profile, bound to checkpoint, maps, inputs and backgrounds.
* `early_alignment_probe.json`: actual result of the known failed-record probe.
* `cache_reuse.json`: hashes and roles of parent files actually reused.
* `analysis_manifest.json`: actual completion/failure status and execution identity.

If recovery stops, send the last traceback, manifest and alignment-trials file.
Do not loosen tolerances, change the saved map or omit the failed recording.
